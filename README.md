# DSD_project — DMA-Based Pipelined Image-Enhancement Accelerator

One-day hackathon-scoped implementation of the 3x3 grayscale sharpening
accelerator described in `docs/image-enhancement-accelerator-project-specification.md`
(the full 4-week course spec). Today's scope is the **minimum tier only**:
single clock, no CDC/FIFO, no synthesis — see `docs/FROZEN_BASELINE.md` for
the exact frozen parameters and interface.

```

  frame_controller.sv   -- line buffers + sliding 3x3 window + border handling (Person A)

  accelerator_top.sv     -- integration: window stream -> MAC -> output skid buffer

golden_model/
  golden_sharpen.py      -- independent Python/numpy reference (Person C)
  gen_test_image.py      -- generates test images + golden expected output as .hex
  compare.py              -- pixel-exact diff between RTL output and golden output
  vectors/                -- generated test images (gitignored contents regenerated by run_sim.sh)

  tb_top.sv                 -- clock/reset, instantiates DUT + source/sink, writes output hex + VCD

scripts/

docs/
```

## Running it

Requires Icarus Verilog (`iverilog`/`vvp`) and Python 3 + numpy.

```bash
./scripts/run_sim.sh
```

This regenerates all test vectors, compiles the RTL + testbench, runs 9
test cases (clean, constant, impulse, checkerboard, all-zero, all-max,
2x random, 1x combined-stress), and compares each against the golden
model. A waveform (`sim_out/wave.vcd`) is written on every run for the
demo — open with `gtkwave sim_out/wave.vcd`.

To run the 4x4 fallback size (see `docs/FROZEN_BASELINE.md`):

```bash
python3 golden_model/gen_test_image.py --size 4 --pattern random --seed 1 --name small4
iverilog -g2012 -Ptb_top.WIDTH=4 -Ptb_top.HEIGHT=4 -o sim_out/sim4.out \
    rtl/line_buffer.sv rtl/frame_controller.sv rtl/mac_pipeline.sv rtl/accelerator_top.sv \
    tb/stream_source.sv tb/stream_sink.sv tb/tb_top.sv
vvp sim_out/sim4.out +INPUT=golden_model/vectors/small4_input.hex \
    +OUTPUT=sim_out/small4_rtl.hex +SIZE=4 +GAPS=1 +STALLS=1 +SEED=4
python3 golden_model/compare.py --expected golden_model/vectors/small4_expected.hex \
    --actual sim_out/small4_rtl.hex --size 4
```

## Two real bugs found and fixed during bring-up (worth reading before you touch `frame_controller.sv`)

Both are documented in comments at their fix sites, summarized here because
they're exactly the class of bug the full spec's risk register (Section 20)
calls out as the top risk ("border/window off-by-one") and they are easy to
reintroduce if the window/backpressure logic gets refactored carelessly:

1. **Off-by-one column shift.** `win_valid` was originally computed
   combinationally against the *already-advanced* `x_in`, while the window
   data (`wc0/wc1/wc2`) were registers still holding the *previous* step's
   result. Every output landed one column to the right of where it should
   have. Caught by the impulse-response test (`t2`) — a single bright pixel
   on a black background makes any spatial misalignment obvious immediately.
   **Fix:** window data and window validity are now both pure combinational
   functions of the *same* cycle's state (`step_now`, `x_in`, `y_in`), so
   they can never drift apart. See the comment block above
   `prop_wc0_top` in `frame_controller.sv`.

2. **Line-buffer corruption under backpressure.** The line buffer's write
   enable was gated only by `x_in < WIDTH`, not by whether a step was
   actually being *taken* (`step_now`). During a random input gap or output
   stall, the pipeline can sit at the same `x_in` for several cycles —
   and the write enable fired on every one of them, repeatedly overwriting
   the "two rows back" value with the current row's value before it was
   supposed to shift. Invisible on the clean (no-gaps, no-stalls) path;
   caught immediately once `+GAPS=1` or `+STALLS=1` was enabled in the
   regression. **Fix:** `lb_wr_en = step_now && (x_in < WIDTH)`.

Both fixes are in the current RTL and covered by the regression (`t0_gaps_stalls`,
`t3_checkerboard` with gaps, `t5_all_max` with stalls, `t6`/`t7` random+gaps/stalls).
If you change the window or line-buffer logic, rerun `scripts/run_sim.sh`
before assuming it still works — the clean path passing is not sufficient
evidence; both bugs above were invisible without gaps/stalls enabled.
